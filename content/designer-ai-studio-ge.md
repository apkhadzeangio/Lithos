# LITHOS — Google AI Studio-ს სატესტო კონფიგურატორი

სატესტო გვერდი: https://lithos.ge/designer/

## მიმდინარე მდგომარეობა

მომზადებულია ცალკე noindex გვერდი, მთავარი საიტის ნავიგაციის შეცვლის გარეშე. მომხმარებელი ირჩევს 103 არსებული მასალიდან ერთს, ტვირთავს სამზარეულოს ფოტოს და სურვილისამებრ უთითებს ფორმას და ზომებს სანტიმეტრებში. ფოტო ბრაუზერშივე მცირდება მაქსიმუმ 1600 პიქსელამდე და JPG-ში ხელახლა იწერება. სამუშაო ფაილები სერვერზე არ იტვირთება ინსტრუქციის მომზადებისას.

ამ ეტაპზე მოქმედი გზა: ინსტრუქციის მომზადება/კოპირება/ჩამოტვირთვა, სივრცისა და ქვის ფოტოების ჩამოტვირთვა და AI Studio-ში ხელით გამოცდა. ავტომატური გენერაცია საჯარო გვერდზე გამორთულია. შედეგის ნიმუში ხელოვნურად არ შეგვიქმნია და არ გამოგვიცხადებია რეალურ გენერაციად.

2026-10-25 შემოწმებისას AI Studio-ს ანგარიშის API პანელი გაიხსნა, მაგრამ პროექტების ჩამონათვალზე დაბრუნდა „Failed to list imported projects: permission denied. Please try again.“ გასაღების შექმნის ფანჯარაში ჩანდა „No Cloud Projects Available“. ეს არ ადასტურებს, რომ ანგარიშს პროექტები საერთოდ არ აქვს — მათი წაკითხვა ვერ მოხერხდა. ახალი გასაღები, ფასიანი რესურსი ან ფასიანი გენერაცია არ შექმნილა.

## ანგარიშის გამართვა

1. AI Studio-ში: https://aistudio.google.com/api-keys — შეამოწმეთ პროექტების მართვის წვდომა. საჭიროების შემთხვევაში პროექტი შექმენით ან შემოიტანეთ იმ ანგარიშით, რომელსაც მისი მართვის უფლება აქვს.
2. პროექტზე გამართეთ Cloud Billing; გადახდისა და პირობების მიღების ეტაპი ანგარიშის მფლობელმა უნდა შეასრულოს.
3. შექმენით მხოლოდ ამ ინტეგრაციისთვის განკუთვნილი Gemini API გასაღები. გასაღები ჩატში ან საჯარო კოდში არ ჩასვათ. API და Gemini Pro გამოწერის ლიმიტები ერთმანეთისგან დამოუკიდებელია.
4. მოდელი: `gemini-nano-banana-2.1`. პირველ ტესტში: ერთი 1K შედეგი; სამზარეულო პირველი სურათია, ქვის ნიმუში მეორე. რეალურ API-ზე ხელმისაწვდომობა და ვიზუალური ხარისხი ჯერ არ შემოწმებულა.

## ავტომატური ნაწილის კოდი

`server/designer/worker.mjs` ცალკე Cloudflare Worker-ისთვისაა მომზადებული. არსებული Sites პროექტი სტატიკურია; ეს Worker ავტომატურად არ გამოქვეყნებულა და მთავარ საიტს არ ცვლის. საჭიროა ცალკე Worker-ის განთავსება ანგარიშის მფლობელის Cloudflare ანგარიშში ან მხარდაჭერილი სერვერული განთავსების სხვა გზის გამართვა.

Worker-ს სჭირდება ორი საიდუმლო პარამეტრი:

- `GEMINI_API_KEY`: Google-ის API გასაღები; მხოლოდ სერვერზე.
- `TEST_ACCESS_TOKEN`: მინიმუმ 32 სიმბოლოს შემთხვევითი საცდელი კოდი. ეს Google-ის გასაღები არ არის; კონფიგურატორში მხოლოდ ამ საცდელ კოდს ვუთითებთ. ბრაუზერში შეყვანილი კოდი მეხსიერებაში რჩება და localStorage-ში არ ინახება.

მომზადებულია `wrangler.jsonc` Durable Object-ის დღიური მრიცხველით. Cloudflare-ის ოფიციალური CLI-ის უკვე გამართულ გარემოში:

```sh
node scripts/build-designer-catalog.mjs
cd server/designer
wrangler secret put GEMINI_API_KEY
wrangler secret put TEST_ACCESS_TOKEN
wrangler deploy
```

მიღებული Worker URL-ის `/generate` მისამართი ჩაიწერება `dist/designer/config.js`-ის `endpoint` ველში. იქ მხოლოდ საჯარო URL უნდა იყოს — არც Google-ის გასაღები და არც საცდელი კოდი. ამის შემდეგ საჭიროა გვერდის ხელახალი გამოქვეყნება.

გათვალისწინებულია:

- ნაგულისხმევად დღეში მაქსიმუმ 20 მცდელობა მთელ სატესტო სისტემაზე, UTC დღის მიხედვით; მინიმუმ 30 წამი მცდელობებს შორის.
- მცდელობა ლიმიტიდან იკლებს ფასიან მოთხოვნამდე; წარუმატებელ მცდელობას ავტომატურად არ ვიმეორებთ.
- ლიმიტი ითვლის მცდელობებს, თანხის ზუსტ ზედა ზღვარს არ წარმოადგენს. ცალკე უნდა გამართოთ Google-ის ბილინგის კონტროლი და სერვერის ხარჯები.
- მხოლოდ ავტორიზებული სატესტო წვდომა; საჯაროდ გახსნამდე საჭიროა მომხმარებელთა ცალკე ლიმიტები და ბოტებისგან დაცვა.
- სერვერული კატალოგი იღებს მხოლოდ არსებულ მასალის ID-ს; მომხმარებლის მიერ მოწოდებული გარე URL ან პრომტი არ გამოიყენება.
- მაქსიმუმ 3 მბ მოთხოვნა / 2 მბ მომზადებული JPEG. ფოტოები/ინსტრუქციები კოდის მიერ ბაზაში ან ლოგებში არ ინახება.
- Google-ში `store:false`; ეს თიშავს Interactions-ის საუბრის მდგომარეობის შენახვას, მაგრამ არ ნიშნავს Google-ის ყველა ტექნიკური ან უსაფრთხოების მონაცემის ნულოვან შენახვას.
- ორი საცნობარო სურათი, ერთი 1K შედეგი, ფიქსირებული მოდელი; Google-ის პასუხის უსაფრთხო დამუშავება და შეცდომისას გასაღების არგამჟღავნება.
- ფოტო Google-ს მხოლოდ მომხმარებლის ცალკე მონიშნული თანხმობით გაეგზავნება.

პირველი ვერსია ცვლის არსებულ სამუშაო ზედაპირს და ინარჩუნებს ფოტოს განლაგებას. ფოტოს გარეშე ზომებით სრული სამზარეულოს აგება ამ ეტაპში არ შედის. ვიზუალიზაცია ტექნიკური ნახაზი არ არის. ქვის ვენების, ფერისა და გეომეტრიის შენარჩუნება რეალურ საცდელ გენერაციებზე უნდა შევაფასოთ.
