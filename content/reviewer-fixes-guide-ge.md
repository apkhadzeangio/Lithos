- საჯარო გვერდებზე აღარ ჩანს `[შესავსები]` ან შიდა ტექნიკური შენიშვნები. `projects-data.js`-ის ცარიელი/placeholder მასალა და ქალაქი არც ბარათში და არც დიალოგში არ იხატება.

- ფორმა ამოწმებს სახელსა და ტელეფონს, ყველა შევსებული ველიდან ქმნის შეტყობინებას და ხსნის WhatsApp-ს ახალ ჩანართში. შეტყობინება მომხმარებელმა თავად უნდა გაგზავნოს. popup-ის დაბლოკვის შემთხვევისთვის ჩნდება პირდაპირი ბმული. ფოტო ფორმიდან ამოღებულია; მომხმარებელს ვთხოვთ, გამოგვიგზავნოს WhatsApp-ში.
- ქართულ ძიებას ესმის ფერები, გავრცელებული სახელები და ქართული/ლათინური დამწერლობის ვარიანტები. „მარმარილოს“ ძიებაში გამოჩნდება მარმარილოს ნახატის მქონე NEOLITH და კვარცი, შესაბამისი განმარტებით; ეს მათ ბუნებრივ მარმარილოდ არ ასაღებს. ცარიელ შედეგებში მოთხოვნით ხელმისაწვდომი კატეგორიები და კონტაქტია.
- უცნობი მონაცემების ფილტრები და გამორთული ტონის ველი წაშლილია. ტექნიკურ დეტალებში უცნობი მნიშვნელობა კვლავ „დააზუსტეთ“-ითაა აღნიშნული.

- მასალის ფანჯრიდან კონკურენტების ბმულები ამოღებულია; NEOLITH-ის ფოტოებს დარჩა მხოლოდ არაბმულოვანი კრედიტი.
- დიზაინი და პალიტრა შენარჩუნებულია. `/lab/` უცვლელია და მთავარ გვერდზე არ გადმოტანილა.

## საერთო მონაცემების შევსება

შეავსეთ `dist/site-config.js`, შემდეგ გაუშვით `node scripts/build-public-pages.mjs`.

- warranty: გარანტიის რეალური ვადა და პირობები.
- timeline.measurement / fabrication / installation: რეალური ვადები.
- workshop: საამქროს დადასტურებული ინფორმაცია.
- serviceArea: ქალაქების/რეგიონების მასივი. შევსების შემდეგ ეს ინფორმაცია აისახება საიტზეც და JSON-LD-ის areaServed-შიც.
- seoCity: თუ კონკრეტული ქალაქის დამატება გსურთ მთავარ SEO სათაურში; ცარიელი მნიშვნელობისას ქალაქი არ იწერება.
- address და mapsUrl: რეალური მისამართი და HTTPS Google Maps ბმული; ცარიელი ნაწილის ელემენტი არ იხატება.
- geo: მხოლოდ დადასტურების შემდეგ `{latitude: ..., longitude: ...}`; მისამართის გარეშე JSON-LD-ში არ ემატება.
- priceCalculation, measurementTerms, careInstructions: რეალური პირობები და მასალის ტიპის მიხედვით მოვლა.
- email: Gmail-იდან `info@lithos.ge`-ზე გადასასვლელად შესაცვლელია მხოლოდ ეს ერთი ხაზი; build აახლებს ოთხივე გვერდის ბმულებსა და JSON-LD-ს.
- 12 პროექტის material და city შეავსეთ `dist/projects-data.js`-ში. ცარიელი დატოვება უსაფრთხოა.

## ლოგო და favicon-ები — უკვე შესრულებულია

საწყისი გამჭვირვალე PNG შენარჩუნებულია. ახალი `assets/lithos-logo-v1.webp` არის 11,264 ბაიტი. დამატებულია 32×32 PNG, 180×180 Apple touch icon და 16/32/48 ზომების favicon.ico. ოთხივე საჯარო HTML ახალ ფაილებს იყენებს; ექსპერიმენტული /lab/ საკუთარ აქტივებს ინარჩუნებს.

მომავალი ექსპორტისთვის:

1. თუ ორიგინალი ვექტორული ლოგო გაქვთ, დიზაინერიდან მიიღეთ ნამდვილი SVG: მხოლოდ საჭირო path-ები, ჩაშენებული raster ფოტოს გარეშე. არსებული PNG-ის SVG კონტეინერში ჩასმა ოპტიმიზაცია არ არის.
2. raster ვარიანტისთვის შეინარჩუნეთ გამჭვირვალობა, შეამცირეთ 256×256-მდე, წაშალეთ EXIF/profile და გამოიტანეთ lossless WebP. მიზანი <30 კბ. გამოყენებული ბრძანება:

   `convert lithos-logo-transparent.png -strip -resize '256x256>' -define webp:lossless=true lithos-logo-v1.webp`
3. favicon-ისთვის გამოიყენეთ ლოგოს ნიშანი წარწერის გარეშე, გამჭვირვალე კვადრატზე უსაფრთხო კიდეებით. 32×32 და 180×180 PNG; ICO — 16/32/48 ზომებით.
4. `/assets/*` ერთი წლით immutable-ად ქეშირდება. შეცვლილ სურათს ახალი სახელი მიეცით (მაგ. `-v2`), ძველ ფაილს იმავე URL-ზე ნუ გადაწერთ.

## Cloudflare და ატვირთვა

არსებულ საიტზე განახლება ამ სამუშაოს ფარგლებში ქვეყნდება. სხვა Cloudflare Pages გარემოში ატვირთეთ **სრული dist საქაღალდის შიგთავსი**, ძირითადი index.html-ით, 404.html-ით, _headers-ითა და ყველა აქტივით. შეცვლილი ფაილების ZIP სრულ საიტს არ ანაცვლებს: მასში მხოლოდ შეცვლილი/ახალი ფაილებია; უცვლელი პროექტების/ფილების ფოტოები არსებულ საქაღალდეში უნდა დარჩეს.

`_headers` დევს საჯარო საქაღალდის ფესვში. იგი შეიცავს immutable ქეშს assets-ზე და მოთხოვნილ HSTS/nosniff/referrer-policy წესებს. Cloudflare Pages/Workers-ის middleware ან cache rules თუ პასუხს ცვლის, საბოლოო HTTP სათაურებიც გადაამოწმეთ. 404.html Cloudflare Pages-ზე გამოიყენება უცნობ მისამართებზე. ლოკალური მარტივი preview სერვერი custom 404 მარშრუტიზაციას არ იმეორებს.

ოფიციალური დოკუმენტაცია:
- https://developers.cloudflare.com/pages/configuration/headers/
- https://developers.cloudflare.com/pages/configuration/serving-pages/

## გამოქვეყნების შემდეგ HTTP შემოწმება

მიმდინარე გამოქვეყნების სერვისზე მთავარი გვერდი და ახალი ლოგო პასუხობს 200-ით; არარსებულ მისამართზე ბრუნდება ახალი ქართული გვერდი 404 სტატუსით. მიმდინარე სერვისი `_headers`-ის წესებს არ იყენებს: ქეშის რეალური სათაურია `public, max-age=0, must-revalidate`, ხოლო მოთხოვნილი HSTS/nosniff/Referrer-Policy HTTP სათაურები არ ჩანს. `_headers` ფაილი სწორადაა მომზადებული Cloudflare Pages-ისთვის, მაგრამ ამ გამოქვეყნების არხში მისი გააქტიურების პარამეტრი არ არის. სტატიკურ ფაილებში მათი გაწერა რეალურ HTTP პასუხს ვერ შეცვლის.

- [ ] ჰოსტინგის მხარეს მოთხოვნილი cache/security HTTP წესების გააქტიურება.
- Referrer-ის მოთხოვნილი პოლიტიკა დამატებით გაწერილია HTML meta-შიც; HSTS და nosniff რეალურ HTTP სათაურებს მოითხოვს.
