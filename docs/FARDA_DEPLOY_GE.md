# farda.lithos.ge — გამოქვეყნების ინსტრუქცია

კოდი მზადდება ცალკე `feat/curtain-studio` branch-ში. `main`-ში გაერთიანება და არსებული production პროექტის შეცვლა ამ სამუშაოში არ ხდება. GitHub რეპოზიტორია: https://github.com/apkhadzeangio/Lithos.

## 1. ცალკე ფრონტენდის პროექტი

Cloudflare Pages-ში შექმენი ცალკე პროექტი ამავე რეპოზიტორიიდან. საწყისი საქაღალდე დატოვე რეპოზიტორიის root-ზე.

| ველი | მნიშვნელობა |
| --- | --- |
| Framework | None |
| Build command | `node scripts/build-farda.mjs` |
| Build output directory | `out-farda` |
| Build environment variable | `NODE_VERSION=24` |
| Review branch | `feat/curtain-studio` |
| Production branch | მომხმარებლის მიერ დამტკიცებული branch; გაერთიანების შემდეგ — `main` |

ალტერნატივაა `out-farda/`-ის შიგთავსის ატვირთვა static hosting-ში. მთავარ LITHOS პროექტში output directory არ შეცვალო: ფარდებისთვის გამოიყენება დამოუკიდებელი პროექტი. არსებული `.openai/hosting.json` ეკუთვნის სხვა Site-ს და ამ დომენისთვის არ გადაიწეროს.

მუშა preview ცალკე, მხოლოდ მფლობელისთვის ხელმისაწვდომ Sites პროექტში ქვეყნდება. ეს ავტომატურად არ ააქტიურებს `farda.lithos.ge`-ს.

## 2. დომენის მიბმა

ახალი hosting პროექტის Custom domains განყოფილებაში დაამატე `farda.lithos.ge`. DNS-ისთვის გამოიყენე უშუალოდ იმ პროექტის მიერ ნაჩვენები ჩანაწერი. არსებული მთავარი დომენის DNS ჩანაწერები არ შეცვალო. დაელოდე დომენის დადასტურებასა და HTTPS-ის გააქტიურებას.

ამ სამუშაოს ფარგლებში Cloudflare ანგარიშზე წვდომა და DNS ცვლილება არ შესრულებულა. შესაბამისად `farda.lithos.ge` ჯერ გამოქვეყნებულ შედეგად არ ითვლება.

## 3. შეკვეთების არხი

ამ ვერსიაში მომხმარებელი ამზადებს WhatsApp-ის შეტყობინებას ნომერზე `+995 551 04 40 13`, თავად ადასტურებს გაგზავნას და ამატებს ფოტოსა და ესკიზს. საჭიროებისას შეცვალე მხოლოდ საჯარო `whatsappPhone` მნიშვნელობა `dist/curtains/config.js`-ში და თავიდან ააგე პროექტი. საიდუმლო გასაღებები ამ ფაილში არ ჩაიწეროს.

`/admin/` არის მომზადებული დამატებითი სერვერის ინტერფეისი. მას WhatsApp-ის შეტყობინებებზე წვდომა არ აქვს და კონფიგურაციის გარეშე შეკვეთებს არ აჩვენებს.

## 4. დამატებითი კერძო სერვერი

პირდაპირ საიტიდან ფოტოების შენახვა და ადმინისტრირება დამოუკიდებელი შემდგომი აქტივაციაა. მომზადებულია `server/curtains/` და `dist/curtains/admin/`. გასააქტიურებლად საჭიროა:

1. ცალკე Worker, D1 მონაცემთა ბაზა `DB` binding-ით და მხოლოდ კერძო R2 bucket `PRIVATE_IMAGES` binding-ით. D1-ში გამოიყენება `schema.sql`.
2. `QUOTA` Durable Object და კონფიგურაციაში არსებული migration/cron. დღიური ლიმიტებია 10 მოთხოვნა ვიზიტორზე და 100 ჯამში; 5-წამიანი შუალედით.
3. Turnstile-ის კონფიგურაცია დომენისთვის და Worker secrets: `TURNSTILE_SECRET_KEY`, 32+ სიმბოლოიანი `QUOTA_SECRET`, 48+ სიმბოლოიანი `ADMIN_TOKEN`.
4. ზუსტი `ALLOWED_ORIGINS` და `TURNSTILE_HOSTNAMES`. საიდუმლოებები მხოლოდ Worker secrets-ში. `.dev.vars.example` შეიცავს ცარიელ სახელებს; რეალური ფაილი Git-ში არ ინახება.
5. 30-დღიანი წაშლისა და cron-ის გადამოწმების შემდეგ `RETENTION_ENABLED=true`.
6. მომხმარებლის ფორმაში პირდაპირი API submit-ისა და Turnstile-ის ინტეგრაცია, რეალურ storage-ზე გამშვები ტესტი და შესაბამისი კონფიდენციალურობის ტექსტის განახლება. მარტო `apiBase`-ის შევსება ამ ფუნქციას არ რთავს.

სერვერის მისამართი ადმინისტრატორისთვის იწერება საჯარო `apiBase`-ში; ადმინისტრატორის ტოკენი რჩება მხოლოდ სერვერზე და ადმინისტრატორის მიმდინარე სესიის მეხსიერებაში.

ფოტორეალისტური AI ცალკე დამატებაა: მომზადებულია ორი რეალური reference ფოტოს მომთხოვნი adapter. წარმოებაში საჭიროა პროვაიდერის გამართვა, რეალური გამოსახულებების შეფასება, ხარჯის ლიმიტები და მომხმარებლის ცალკე ინფორმირება გარე დამუშავებაზე. ამ ეტაპზე ის არ იძახება.

## 5. გაშვების მიღების კრიტერიუმები

მობილურზე გადაამოწმე კამერა, საკუთარი ფოტოს ატვირთვა, ქსოვილი/დიზაინი, ფანჯარაზე მორგება და WhatsApp-ში ტექსტისა და ორივე სურათის გაგზავნა. გადაამოწმე მიმღები ნომრის მუშაობა. მომწოდებელთან დაადასტურე კონკრეტული ქსოვილის ფერი, მარაგი, ფასი და შერჩეული შეკერვა. საჯარო კატალოგში არსებობა LITHOS-ის ხელმისაწვდომ მარაგს არ ნიშნავს.

Cloudflare-ის ოფიციალური ცნობები: [Pages build image](https://developers.cloudflare.com/pages/configuration/build-image/) და [FLUX.2 Klein multi-reference contract](https://developers.cloudflare.com/changelog/post/2026-01-15-flux-2-klein-4b-workers-ai/). მომავალი AI ინტეგრაციის reference სურათები წინასწარ უნდა შემცირდეს 512×512-ზე ნაკლებ ზომამდე.
